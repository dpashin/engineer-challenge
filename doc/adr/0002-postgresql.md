# 2. postgresql

Дата: 2026-03-10

## Контекст

Нужно хранить данные для авторизации: пользователи, токены и т.п.

## Решение

Выбираем postgresql

### Компромиссы

Postgresql делаем одним контейнером, а не master/slave.
Мотивация: Делаем MVP, не хочется тратить время на настройку репликации.

## Последствия (Consequences)

### Плюсы
- структура данных хорошо ложится в реляционную базу данных.
- opensource, современный стандарт
- легко укладывается в контейнер
- Есть большой опыт работы, нет порога вхождения.
